# Feature Specification: 思源一键导出（SiYuan Note Export）

**Feature Branch**: `001-siyuan-note-export`

**Created**: 2026-11-09

**Status**: Draft

**Input**: User description: "我想给 dsh agent 做一个插件：对话过程中完成对话后，加一个按钮，把单次输出导出到思源笔记中；调用大模型，有弹窗，默认给一个文件主题名，可以选择思源存放路径；导出内容格式带小图标，样式清晰容易阅读。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一键把单次输出导出为思源笔记 (Priority: P1)

作为日常用 dsh 对话并积累笔记的用户，我在助手完成一次回复后，想直接点击这条回复旁的「导出到思源」按钮，经过一个弹窗确认，就把这条输出保存为一篇格式清晰、带小图标的思源笔记，而不用手动复制粘贴再排版。

**Why this priority**: 免手动复制、直接归档到知识库是本特性的核心价值；没有这一条，其余能力都无从谈起。

**Independent Test**: 完成一次对话，点击该条回复的导出按钮，在弹窗中直接确认，检查所选思源路径下出现一篇结构化、带小图标的新笔记。

**Acceptance Scenarios**:

1. **Given** 助手已完成一次回复，**When** 查看该条回复的操作栏，**Then** 存在「导出到思源」按钮。
2. **Given** 用户点击该按钮，**When** 导出弹窗打开，**Then** 主题名输入框已预填大模型生成的默认主题名，存放路径优先为上次成功导出的位置，无记录时用设置中的默认存放路径，两者都无则提示选择。
3. **Given** 用户未修改任何内容，**When** 点击弹窗中的「导出」，**Then** 所选路径下创建一篇以主题名命名的新笔记，内容为该条回复的结构化版本。
4. **Given** 导出成功，**When** 查看弹窗反馈，**Then** 显示成功提示（含落点路径），按钮恢复可用。

---

### User Story 2 - 挑选并记住思源存放位置 (Priority: P2)

作为对笔记归档位置有明确规划的用户，我想在弹窗里直接浏览思源的笔记本与文档层级、任选一个位置存放，并让系统记住我上次成功导出的位置，下次默认就用它。

**Why this priority**: 存放位置选错会让笔记"失踪"；路径记忆减少重复操作，是高频导出体验的关键。

**Independent Test**: 打开弹窗，展开文档树切换到另一个子文档位置并导出成功；下次再打开弹窗，确认默认路径为该位置。

**Acceptance Scenarios**:

1. **Given** 导出弹窗打开，**When** 查看路径选择区，**Then** 展示思源的笔记本与文档层级树。
2. **Given** 文档树已展开，**When** 用户选中某个笔记本或子文档层级，**Then** 该位置成为本次导出目标并在弹窗中即时显示。
3. **Given** 曾成功导出到某路径，**When** 下次打开弹窗，**Then** 默认路径为该位置。
4. **Given** 用户选择了新路径并导出成功，**When** 再次导出，**Then** 默认路径更新为最近一次成功的位置。

---

### User Story 3 - 出错可恢复、内容不丢 (Priority: P3)

作为导出失败时仍想保住内容的用户，我想在出错时看到明确原因和「重试」入口，我已填的主题名和已选的路径不被清空，且不会因为重复点击产生重复笔记。

**Why this priority**: 失败场景决定用户敢不敢把导出当作可靠归档手段；但它依赖 P1/P2 的主流程才能独立测试。

**Independent Test**: 断开思源后点击导出，确认显示失败原因与重试入口且已填内容保留；恢复后重试成功；快速连点导出按钮确认只产生一篇笔记。

**Acceptance Scenarios**:

1. **Given** 思源当前不可用，**When** 用户点击导出，**Then** 弹窗显示明确的失败原因与「重试」，已填主题名与已选路径保留。
2. **Given** 大模型生成默认主题名失败，**When** 弹窗打开，**Then** 主题名回退为回复开头文本的截断版，用户仍可继续导出。
3. **Given** 一次导出正在进行，**When** 用户再次点击导出按钮，**Then** 按钮呈进行中状态，不产生重复提交。
4. **Given** 主题名包含不适合文档名的字符，**When** 创建笔记，**Then** 自动清理为合法名称后再创建。

---

### User Story 4 - 从侧栏打开导出设置 (Priority: P2)

作为希望按自己习惯控制导出行为的用户，我想在 dsh 左侧栏找到一个「导出设置」入口，点击后在主工作区打开设置面板，查看和修改默认存放路径、以及是否在导出时显示弹窗，而不用去翻配置文件。

**Why this priority**: 静默导出与默认路径都依赖一处可发现的配置；没有它，用户无法关闭弹窗或指定落点。它独立于导出主流程，可单独交付验证。

**Independent Test**: 点击侧栏入口打开设置面板，修改默认路径并关闭弹窗开关；随后导出一次，确认不再弹窗且笔记落到设置的位置。

**Acceptance Scenarios**:

1. **Given** 插件已装载，**When** 查看 dsh 左侧栏，**Then** 存在带 `biji.svg` 图标和可访问名称的「导出设置」入口。
2. **Given** 用户点击该入口，**When** 设置面板打开，**Then** 它在主工作区以 tab/面板呈现，不以模态遮罩阻塞对话。
3. **Given** 设置面板打开，**When** 查看配置项，**Then** 能看到默认存放路径与「导出时显示弹窗」开关，开关默认为开。
4. **Given** 用户把开关改为关，**When** 直接返回对话并导出，**Then** 后续导出按静默模式执行，无需重启。
5. **Given** 用户通过思源文档树选择新的默认路径，**When** 保存后再次导出，**Then** 使用新的默认路径；弹窗模式在没有上次成功路径时同样使用它。
6. **Given** 思源当前不可用，**When** 打开设置面板，**Then** 显示可理解的原因，并保留上一次有效配置不被清空。

---

### User Story 5 - 静默一键导出、不打断对话 (Priority: P2)

作为不想每次导出都确认的用户，我在设置中关闭弹窗后，点击回复旁的导出按钮就直接在后台生成并写入思源；按钮显示运行中状态，完成后用非阻塞提示告诉我落在哪，期间我可以继续对话或切换会话。

**Why this priority**: 这是本 Change 的核心新能力；默认仍保留弹窗，静默是可选模式，因此与 US4 同属 P2。

**Independent Test**: 关闭弹窗开关，点击一条回复的导出按钮，不出现弹窗；按钮进入加载态，期间可继续输入；完成后出现含落点的提示，思源目标位置出现新笔记。

**Acceptance Scenarios**:

1. **Given** 弹窗开关为关，**When** 点击某条回复的导出按钮，**Then** 不弹出任何确认框，立即开始后台导出。
2. **Given** 静默导出进行中，**When** 查看该按钮，**Then** 呈加载/运行状态且不可重复触发；同一回复不会产生第二篇笔记。
3. **Given** 静默导出进行中，**When** 用户继续输入、发送消息或切换会话/面板，**Then** 对话不被阻塞，导出继续执行。
4. **Given** 设置中已配置默认路径，**When** 静默导出完成，**Then** 笔记落在该路径。
5. **Given** 设置中未配置默认路径，**When** 静默导出完成，**Then** 笔记落在当前笔记本的文档树根目录。
6. **Given** 静默导出成功，**When** 查看提示，**Then** 以非阻塞方式显示落点，数秒后自动消失，不要求用户关闭。
7. **Given** 静默导出失败，**When** 查看提示，**Then** 显示可理解的原因并提供「重试」，不自动打开弹窗。
8. **Given** 两条不同回复先后发起静默导出，**When** 两者都进行中，**Then** 互不阻塞，各自只产生一篇笔记。

---

### Edge Cases

- 回复为空或只有一张图片 → 不出现导出按钮，或导出时给出提示，不产生空笔记。
- 回复极长（数万字）→ 照常完成导出，不截断。
- 导出过程中用户关闭弹窗 → 取消本次导出，不留下半成品笔记。
- 目标存放路径在导出前被删除 → 提示重新选择路径。
- 思源中已存在同名文档 → 新建独立文档，不覆盖、不合并已有笔记。
- 导出途中服务中断 → 失败提示可重试，重试成功后只产生一篇笔记。
- 同一条回复连续导出到不同路径 → 各自独立成文，互不影响。
- 静默模式下设置路径已被删除或无权限 → 提示失败与原因，不静默改写到其他位置。
- 静默导出进行中用户修改设置或切换开关 → 本次导出按发起时的模式与目标完成，新设置只影响下一次。
- 静默导出期间关闭窗口或宿主重启 → 不留下半成品笔记；该次导出视为失败，恢复后可重新发起。
- `biji.svg` 加载失败 → 入口仍显示可访问名称，不出现无名称的空白可点击区域。
- 设置文件损坏或缺失 → 回到默认值（显示弹窗、无默认路径），插件仍可用。
- 思源没有任何笔记本 → 静默导出失败并提示先创建笔记本；设置中的路径选择显示空态。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 每条助手回复的操作栏 MUST 提供「导出到思源」按钮。
- **FR-002**: 当「导出时显示弹窗」开启时，点击按钮 MUST 打开导出弹窗，弹窗 MUST 包含主题名输入框与存放路径选择区；开关关闭时的行为见 FR-017。
- **FR-003**: 系统 MUST 调用大模型完成两件事：生成默认主题名；将该条回复重排为结构化笔记正文。
- **FR-004**: 用户 MUST 能够在弹窗中编辑主题名，覆盖大模型给出的默认值。
- **FR-005**: 存放路径选择区 MUST 展示思源的笔记本与文档层级，用户可任选一层作为目标位置。
- **FR-006**: 系统 MUST 记住最近一次成功导出的存放路径，并将其作为下次打开弹窗时的默认值；尚无成功记录时 MUST 使用设置中的默认存放路径（FR-015），两者都没有时 MUST 要求用户选择。
- **FR-007**: 导出产物 MUST 是所选路径下以主题名命名的独立新笔记；导出 MUST NOT 改动或覆盖已有笔记。
- **FR-008**: 导出范围 MUST 仅限该条助手回复的正文，不含用户提问与工具执行过程；代码块、列表等原有结构 MUST 保留。
- **FR-009**: 结构化笔记 MUST 层级清晰（明确的标题分节、列表、代码块），要点 MUST 以小图标标注，打开即可读。
- **FR-010**: 导出失败 MUST 显示用户可理解的失败原因并提供重试入口，且 MUST 保留用户已填的主题名与已选路径。
- **FR-011**: 导出进行中 MUST 防止重复提交，一次确认只产生一篇笔记。
- **FR-012**: 导出成功 MUST 给出成功反馈，包含笔记落点位置。
- **FR-013**: 调用大模型（生成主题名、重排正文）时，输入 MUST 仅包含该条单次输出本身与完成该任务所需的最小指令，MUST NOT 携带完整对话上下文，以节省 token。
- **FR-014**: dsh 左侧栏 MUST 提供带 `biji.svg` 图标与可访问名称的「导出设置」入口；点击 MUST 在主工作区以 tab/面板打开设置，MUST NOT 以模态遮罩阻塞对话。
- **FR-015**: 设置 MUST 展示并允许修改「默认存放路径」；选择方式 MUST 为思源的笔记本与文档层级，MUST NOT 接受本机文件系统路径。
- **FR-016**: 设置 MUST 提供「导出时显示弹窗」开关，默认开启；变更 MUST 无需重启即对后续导出生效。
- **FR-017**: 开关关闭时，点击导出按钮 MUST NOT 打开弹窗，MUST 立即在后台发起静默导出。
- **FR-018**: 静默导出 MUST 优先使用设置中的默认存放路径；未配置时 MUST 使用「当前笔记本」的文档树根目录（定义见 Assumptions：最近成功导出所在笔记本 → 首个未关闭笔记本）。
- **FR-019**: 静默导出期间，该条回复的按钮 MUST 呈加载/运行状态并阻止重复提交；MUST NOT 阻塞对话输入、发送、切换会话或切换面板。
- **FR-020**: 静默导出成功 MUST 以非阻塞提示展示落点；失败 MUST 展示可理解的原因并提供「重试」，MUST NOT 自动打开弹窗。
- **FR-021**: 静默导出 MUST 复用与弹窗导出相同的模型生成与写入流程，输入范围仍 MUST 仅限单次输出（FR-013）。
- **FR-022**: 导出偏好 MUST 持久化并在重启后保留；配置缺失或损坏时 MUST 回退到默认值（显示弹窗、无默认路径）并保持可用。
- **FR-023**: 静默导出的目标路径在导出时不可用（被删除或无权限）时 MUST 失败并说明原因，MUST NOT 静默改写到其他位置。
- **FR-024**: 侧栏入口与设置面板 MUST 支持键盘操作与中英双语文案；图标加载失败时 MUST 保留可访问名称。
- **FR-025**: 不同回复的静默导出 MUST 互不阻塞；同一条回复 MUST 同时只有一次进行中的导出；弹窗与静默模式共用同一 Host 幂等键，不各自实现一套去重。

### Key Entities

- **单次输出（导出源）**：一条助手回复的正文，含文本、标题、列表与代码块；是导出的唯一内容来源。
- **导出请求**：用户在弹窗中确认的一次导出意图，含主题名、目标存放路径，以及对单次输出的引用；确认前主题名可编辑。
- **结构化笔记**：导出产物的数据形状——主题名（即笔记标题）、分节正文、小图标要点标注，以及导出时间与来源会话标识。
- **存放路径**：目标在思源中的位置，由「笔记本 + 文档层级」组成，经文档树选择得到。
- **导出任务状态**：待确认 → 生成中 → 成功 / 失败（失败必带原因）。
- **导出偏好**：插件级配置，含默认存放路径与「导出时显示弹窗」开关；跨会话与重启保留，缺失时回退默认值。
- **静默导出任务**：无弹窗发起的后台导出，含所属单次输出、目标位置、状态（生成中 / 写入中 / 成功 / 失败）与可重试标记。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从回复完成到笔记落盘，全程不超过 3 次点击（打开弹窗 → 确认导出 → 完成）。
- **SC-002**: 正常情况下，95% 的导出在 30 秒内完成。
- **SC-003**: 导出的笔记无需二次编辑即可阅读归档：具备清晰的标题层级、要点带小图标，抽样评估 ≥ 90% 的导出达到该标准。
- **SC-004**: 默认主题名与内容相关，≥ 80% 的导出中用户无需修改主题名即可保存。
- **SC-005**: 失败场景 100% 给出明确原因与重试入口，用户已填内容不丢失。
- **SC-006**: 导出不产生意外的重复笔记或半成品笔记（0 例）。
- **SC-007**: 设置变更后，下一次导出的行为与设置一致（100%），且无需重启。
- **SC-008**: 静默导出从点击到出现结果提示，95% 在 30 秒内完成；期间对话输入与发送不被阻塞（0 次）。
- **SC-009**: 静默导出结果 100% 对用户可见：成功含落点，失败含原因与重试入口，不依赖用户打开弹窗。
- **SC-010**: 用户从侧栏进入设置并完成一次修改，交互不超过 4 次（打开入口 → 定位配置项 → 修改 → 生效）。
- **SC-011**: 同时发起 3 条不同回复的静默导出，各自完成且每条只产生 1 篇笔记（重复 0、丢失 0）。

## Assumptions

- **已确认（Q1=A）**：大模型职责 = 生成默认主题名 + 将回复重排为带小图标的结构化笔记；不做改写、翻译或摘要。
- **已确认（Q2=A）**：导出按钮出现在每条助手回复的操作栏上。
- **已确认（Q3=A）**：路径选择为弹窗内嵌的思源文档树选择器，并记住上次成功导出的位置。
- 小图标采用通用表情符号（如 ✅ 📌 ⚠️ 💡），无需额外资源即可显示。
- 思源在本机运行、用户已登录并至少拥有一个笔记本；导出写入用户所选位置。
- 大模型连接复用宿主现有配置，用户无需为本特性单独配置模型。
- 「记住的路径」等偏好保存在本地，随用户环境持久保留。
- 思源允许同名文档并存；导出始终新建文档，不做同名检测合并。
- 主题名由用户确认后即视为最终文档名，导出后不在思源内自动改名。
- **已确认（Q4=A）**：静默导出落点 = 设置中的默认存放路径优先；未配置时使用当前笔记本的文档树根目录。
- 「当前笔记本」无官方活动笔记本 API：取最近一次成功导出所在笔记本；无成功记录时取 `lsNotebooks` 返回的第一本未关闭笔记本（research R7）。
- **已确认（Q5=A）**：静默导出结果用非阻塞 toast 提示，成功含落点、失败含原因。
- **已确认（Q6=A）**：静默导出失败提供「重试」入口，不自动切换到弹窗。
- 导出偏好是插件级全局设置，作用于所有会话与窗口，宿主侧重启后保留；默认「显示弹窗」。
- 「思源笔记路径」指存放路径（笔记本 + 文档层级），不是本机文件系统目录。
- 静默导出复用与弹窗导出相同的模型生成与写入流程，仍只发送单次输出。
- 静默模式不提供取消入口；进行中按钮加载并禁用。
- 弹窗预填顺序保持不变：上次成功路径优先，其次设置默认路径，均无则要求用户选择。
- 侧栏入口图标使用项目根 `biji.svg`，随客户端资源打包；面板样式遵循 app screen 规则（无渐变、无玻璃拟态、无发光，控件可键盘操作）。

## 不在范围内 (Out of Scope)

| 不做的事 | 为什么不做 | 以后会不会做 |
|---|---|---|
| 导出整段对话或批量导出历史会话 | 需求明确为「单次输出」 | 可能，按会话导出 |
| 导出到 Notion / Obsidian 等其他笔记工具 | 本期只对接思源 | 可能 |
| 笔记在思源内的同步、双链、标签管理 | 属于思源自身能力 | 否，交给思源 |
| 对回复内容做改写、翻译或生成摘要 | 保持输出忠实；结构化重排 ≠ 改写 | 可能 |
| 图片等富媒体资源的完整搬运 | v1 以占位或引用方式保留 | 可能 |
| 导出后的笔记再编辑回写到对话 | 本期为单向导出 | 可能 |
| 按会话或工作区分别配置导出偏好 | 本期为插件级全局设置，避免状态组合过多 | 可能 |
| 静默导出的队列页、历史记录与操作系统级通知 | 非阻塞提示已满足「知情但不打扰」 | 可能 |
| 设置项云端同步或多设备共享 | 仅面向本机使用 | 否 |
