# Feature Specification: 思源一键导出（SiYuan Note Export）

**Feature Branch**: `001-siyuan-note-export`

**Created**: 2026-11-09

**Status**: Draft

**Input**: User description: "我想给 dsh agent 做一个插件：对话过程中完成对话后，加一个按钮，把单次输出导出到思源笔记中；调用大模型，有弹窗，默认给一个文件主题名，可以选择思源存放路径；导出内容格式带小图标，样式清晰容易阅读。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一键把单次输出导出为思源笔记 (Priority: P1)

作为日常用 dsh 对话并积累笔记的用户，我在助手完成一次回复后，想直接点击这条回复旁的「导出到思源」按钮，经过一个弹窗确认，就把这条输出保存为一篇格式清晰、带小图标的思源笔记，而不用手动复制粘贴再排版。

**Why this priority**: 免手动复制、直接归档到知识库是本特性的核心价值；没有这一条，其余能力都无从谈起。

**Independent Test**: 完成一次对话，点击该条回复的导出按钮，在弹窗中直接确认，检查所选思源路径下出现一篇结构化、带小图标的新笔记。

**Acceptance Scenarios**:

1. **Given** 助手已完成一次回复，**When** 查看该条回复的操作栏，**Then** 存在「导出到思源」按钮。
2. **Given** 用户点击该按钮，**When** 导出弹窗打开，**Then** 主题名输入框已预填大模型生成的默认主题名，存放路径为上次成功导出的位置。
3. **Given** 用户未修改任何内容，**When** 点击弹窗中的「导出」，**Then** 所选路径下创建一篇以主题名命名的新笔记，内容为该条回复的结构化版本。
4. **Given** 导出成功，**When** 查看弹窗反馈，**Then** 显示成功提示（含落点路径），按钮恢复可用。

---

### User Story 2 - 挑选并记住思源存放位置 (Priority: P2)

作为对笔记归档位置有明确规划的用户，我想在弹窗里直接浏览思源的笔记本与文档层级、任选一个位置存放，并让系统记住我上次成功导出的位置，下次默认就用它。

**Why this priority**: 存放位置选错会让笔记"失踪"；路径记忆减少重复操作，是高频导出体验的关键。

**Independent Test**: 打开弹窗，展开文档树切换到另一个子文档位置并导出成功；下次再打开弹窗，确认默认路径为该位置。

**Acceptance Scenarios**:

1. **Given** 导出弹窗打开，**When** 查看路径选择区，**Then** 展示思源的笔记本与文档层级树。
2. **Given** 文档树已展开，**When** 用户选中某个笔记本或子文档层级，**Then** 该位置成为本次导出目标并在弹窗中即时显示。
3. **Given** 曾成功导出到某路径，**When** 下次打开弹窗，**Then** 默认路径为该位置。
4. **Given** 用户选择了新路径并导出成功，**When** 再次导出，**Then** 默认路径更新为最近一次成功的位置。

---

### User Story 3 - 出错可恢复、内容不丢 (Priority: P3)

作为导出失败时仍想保住内容的用户，我想在出错时看到明确原因和「重试」入口，我已填的主题名和已选的路径不被清空，且不会因为重复点击产生重复笔记。

**Why this priority**: 失败场景决定用户敢不敢把导出当作可靠归档手段；但它依赖 P1/P2 的主流程才能独立测试。

**Independent Test**: 断开思源后点击导出，确认显示失败原因与重试入口且已填内容保留；恢复后重试成功；快速连点导出按钮确认只产生一篇笔记。

**Acceptance Scenarios**:

1. **Given** 思源当前不可用，**When** 用户点击导出，**Then** 弹窗显示明确的失败原因与「重试」，已填主题名与已选路径保留。
2. **Given** 大模型生成默认主题名失败，**When** 弹窗打开，**Then** 主题名回退为回复开头文本的截断版，用户仍可继续导出。
3. **Given** 一次导出正在进行，**When** 用户再次点击导出按钮，**Then** 按钮呈进行中状态，不产生重复提交。
4. **Given** 主题名包含不适合文档名的字符，**When** 创建笔记，**Then** 自动清理为合法名称后再创建。

---

### Edge Cases

- 回复为空或只有一张图片 → 不出现导出按钮，或导出时给出提示，不产生空笔记。
- 回复极长（数万字）→ 照常完成导出，不截断。
- 导出过程中用户关闭弹窗 → 取消本次导出，不留下半成品笔记。
- 目标存放路径在导出前被删除 → 提示重新选择路径。
- 思源中已存在同名文档 → 新建独立文档，不覆盖、不合并已有笔记。
- 导出途中服务中断 → 失败提示可重试，重试成功后只产生一篇笔记。
- 同一条回复连续导出到不同路径 → 各自独立成文，互不影响。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 每条助手回复的操作栏 MUST 提供「导出到思源」按钮。
- **FR-002**: 点击按钮 MUST 打开导出弹窗，弹窗 MUST 包含主题名输入框与存放路径选择区。
- **FR-003**: 系统 MUST 调用大模型完成两件事：生成默认主题名；将该条回复重排为结构化笔记正文。
- **FR-004**: 用户 MUST 能够在弹窗中编辑主题名，覆盖大模型给出的默认值。
- **FR-005**: 存放路径选择区 MUST 展示思源的笔记本与文档层级，用户可任选一层作为目标位置。
- **FR-006**: 系统 MUST 记住最近一次成功导出的存放路径，并将其作为下次打开弹窗时的默认值。
- **FR-007**: 导出产物 MUST 是所选路径下以主题名命名的独立新笔记；导出 MUST NOT 改动或覆盖已有笔记。
- **FR-008**: 导出范围 MUST 仅限该条助手回复的正文，不含用户提问与工具执行过程；代码块、列表等原有结构 MUST 保留。
- **FR-009**: 结构化笔记 MUST 层级清晰（明确的标题分节、列表、代码块），要点 MUST 以小图标标注，打开即可读。
- **FR-010**: 导出失败 MUST 显示用户可理解的失败原因并提供重试入口，且 MUST 保留用户已填的主题名与已选路径。
- **FR-011**: 导出进行中 MUST 防止重复提交，一次确认只产生一篇笔记。
- **FR-012**: 导出成功 MUST 给出成功反馈，包含笔记落点位置。
- **FR-013**: 调用大模型（生成主题名、重排正文）时，输入 MUST 仅包含该条单次输出本身与完成该任务所需的最小指令，MUST NOT 携带完整对话上下文，以节省 token。

### Key Entities

- **单次输出（导出源）**：一条助手回复的正文，含文本、标题、列表与代码块；是导出的唯一内容来源。
- **导出请求**：用户在弹窗中确认的一次导出意图，含主题名、目标存放路径，以及对单次输出的引用；确认前主题名可编辑。
- **结构化笔记**：导出产物的数据形状——主题名（即笔记标题）、分节正文、小图标要点标注，以及导出时间与来源会话标识。
- **存放路径**：目标在思源中的位置，由「笔记本 + 文档层级」组成，经文档树选择得到。
- **导出任务状态**：待确认 → 生成中 → 成功 / 失败（失败必带原因）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从回复完成到笔记落盘，全程不超过 3 次点击（打开弹窗 → 确认导出 → 完成）。
- **SC-002**: 正常情况下，95% 的导出在 30 秒内完成。
- **SC-003**: 导出的笔记无需二次编辑即可阅读归档：具备清晰的标题层级、要点带小图标，抽样评估 ≥ 90% 的导出达到该标准。
- **SC-004**: 默认主题名与内容相关，≥ 80% 的导出中用户无需修改主题名即可保存。
- **SC-005**: 失败场景 100% 给出明确原因与重试入口，用户已填内容不丢失。
- **SC-006**: 导出不产生意外的重复笔记或半成品笔记（0 例）。

## Assumptions

- **已确认（Q1=A）**：大模型职责 = 生成默认主题名 + 将回复重排为带小图标的结构化笔记；不做改写、翻译或摘要。
- **已确认（Q2=A）**：导出按钮出现在每条助手回复的操作栏上。
- **已确认（Q3=A）**：路径选择为弹窗内嵌的思源文档树选择器，并记住上次成功导出的位置。
- 小图标采用通用表情符号（如 ✅ 📌 ⚠️ 💡），无需额外资源即可显示。
- 思源在本机运行、用户已登录并至少拥有一个笔记本；导出写入用户所选位置。
- 大模型连接复用宿主现有配置，用户无需为本特性单独配置模型。
- 「记住的路径」等偏好保存在本地，随用户环境持久保留。
- 思源允许同名文档并存；导出始终新建文档，不做同名检测合并。
- 主题名由用户确认后即视为最终文档名，导出后不在思源内自动改名。

## 不在范围内 (Out of Scope)

| 不做的事 | 为什么不做 | 以后会不会做 |
|---|---|---|
| 导出整段对话或批量导出历史会话 | 需求明确为「单次输出」 | 可能，按会话导出 |
| 导出到 Notion / Obsidian 等其他笔记工具 | 本期只对接思源 | 可能 |
| 笔记在思源内的同步、双链、标签管理 | 属于思源自身能力 | 否，交给思源 |
| 对回复内容做改写、翻译或生成摘要 | 保持输出忠实；结构化重排 ≠ 改写 | 可能 |
| 图片等富媒体资源的完整搬运 | v1 以占位或引用方式保留 | 可能 |
| 导出后的笔记再编辑回写到对话 | 本期为单向导出 | 可能 |
